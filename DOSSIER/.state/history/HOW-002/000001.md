## Purpose

Releases a new version of todo: a tag on main that makes GitHub Actions build and publish todo.exe and the Linux binary with their SHA-256 files.

## Steps

1. Finish the release task in TODO.md: the version in Cargo.toml, the entry in CHANGELOG.md, the README and docs/json.md.
2. Run the three checks on Windows (cargo fmt, cargo clippy, cargo test --all-features) and the Linux check in WSL.
3. Ask the owner before any push. Then push dev, fast-forward main to dev and push main.
4. Wait until CI on main is green on Windows and Linux (gh run list).
5. Tag that commit vX.Y.Z and push the tag. The release workflow checks the tag against Cargo.toml, runs the tests, builds both programs and publishes them.
6. Build or download the new todo.exe and copy it to %LOCALAPPDATA%\Programs\todo; check with todo --version.
7. Run todo migrate --yes in this repository, then todo check.

## Settings

The workflows are .github/workflows/ci.yml and release.yml. The released files are todo.exe, todo-linux-x86_64 and one .sha256 file for each. CI fails when todo.exe needs a DLL that is not part of Windows, or reaches 5 MB.

## Traps

Tag only after CI on main is green: the tag publishes whatever it points at. A version bump can break tests that use a fixed newer version as data, so run the full suite after it. Install the new todo.exe before this repository uses a new todo.toml key or a new file format: an older todo refuses both, and so does every worker that uses it. A new dependency must be added to NFR-9 in docs/requirements.md and to the allow-list in ci.yml.

## Tested with

Releases v0.6.0 to v1.0.0 (2026-11-18 to 2026-11-22), GitHub Actions runners windows-latest and ubuntu-latest.
