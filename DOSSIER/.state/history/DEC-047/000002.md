## Decision

All workers work in one checkout. A task names the files it may change, and next never hands out a task whose files overlap with a task someone else is working on; claim refuses it with FILES_BUSY. done compares the files its commit changed with the task's files and refuses a commit outside them with OUT_OF_SCOPE. Tasks without files are handed out as before, so existing projects do not stall; level-1 tasks must list files anyway. (Owner, 2026-11-19)

## Reason

Two tasks with no dependency between them still collide when both edit the same file. A worktree per agent wastes disk space (each has its own build folder, 11 GB here) and needs a serial merge.

## Rejected

A worktree per agent; one agent per area: far less parallel; no rule and fixing conflicts afterwards: weak models cannot resolve conflicts; treating a task without files as touching everything.
