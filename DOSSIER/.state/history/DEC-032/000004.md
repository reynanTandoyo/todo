## Decision

A milestone is a piece of work with a goal that is divided into tasks or further milestones, for example "Develop the renderer" with "C shader" and "GPU compiler". It is never a release or version label such as "v0.6". Milestones nest to any depth and todo manages the tree. The tree is logical: entries stay where they are in the file and only the milestone field links them. Help text, tests and fixtures use examples of that kind. (Owner, 2026-11-18)

## Reason

An agent that takes a task must know which larger piece of work it serves and why; a release label tells it nothing.

## Rejected

Milestones as release labels; one level of milestones only (the first plan, replaced the same day).
